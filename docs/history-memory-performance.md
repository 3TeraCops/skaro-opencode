# Истории: учёт памяти и обновления после вытеснения

Продолжение исправлений отзывчивости 19.10.2026 по поручению владельца.
Общий статус — [отчёт об отзывчивости](feed-performance.md).
Дизайн и поведение интерфейса в этом этапе не менялись.

## Изменения

Канонический `Timeline` ведёт оценку сохранённого объёма по отдельным записям
и ходам. Добавление текста учитывает только новые символы; замена записи
пересчитывает эту запись. Полная оценка выполняется при восстановлении
снимка или откате истории. Это логическая оценка строк и структуры данных,
а не измерение фактического heap JavaScript.

`LiveChat` и `ActiveRun` читают текущую оценку из модели. Прежний повторный
рекурсивный обход всей истории при открытии удалён; размер больше не остаётся
равным значению до поступления новых событий. Работающие элементы и фоновые
команды имеют индекс: проверка возможности освободить восстановимую копию
не просматривает все предыдущие записи. Защита вопросов, работы агента,
очередей и текущих операций сохраняется.

Кеш канонических снимков read-model worker ограничен оценкой 32 МиБ и тремя
беседами. Обращение обновляет порядок LRU. Вытеснение происходит после
синхронной операции: запись SQLite и формирование ответа используют
свой полный снимок до завершения. Повторное сохранение уже загруженной
модели не создаёт ещё один `Timeline` и не перестраивает его индексы.

После вытеснения потоковые добавления текста не восстанавливают всю беседу.
Worker читает из `feed_items` только затронутые записи, применяет обычный
канонический reducer и обновляет строки ленты по `feed_targets`.
Запись текста, ревизии, заголовка и номера события источника атомарна.
Общие счётчики читаются из индексированного диапазона и сохраняют полный
размер беседы. Основной формат журналов и пользовательские данные не меняются.

Устранено попадание служебного `turnsIndexed` из метаданных SQLite в
каноническое состояние при восстановлении. Ошибка операции освобождает
кеш: откат SQLite не оставляет в памяти снимок с непринятой добавкой текста.

## Проверено

На изолированной копии настоящего профиля воспроизведены 23 962 события
реального Codex, два сегмента и 339 итоговых записей. В контрольных точках
оценка памяти совпала с независимым восстановлением текущего снимка;
индекс работающих элементов совпал с фактическими статусами записей.
Проверены замены, текстовые добавления, завершение ходов, вопросы и
восстановление элементов страницами по 32.

На настоящем участке потока проверены рост через границу бюджета,
вытеснение и повторное чтение полного текста из SQLite. Для воспроизводимого
перехода через границу использован бюджет 512 006 байт; следующий настоящий
фрагмент увеличил оценку до 512 018. В отдельном режиме с нулевым бюджетом
этот же фрагмент применён к выгруженной беседе: кеш оставался пустым,
полная история и текст после чтения совпали. Проверены счётчики,
ревизия ленты и номер события источника после такого обновления.
Проверен отказ записи настоящей SQLite в режиме `PRAGMA query_only=ON`:
после ошибки исходная история и ревизия сохранились, повторная запись
добавила настоящий фрагмент один раз. Данные не генерировались; API и
backend не подменялись.

Логи целевых проверок: `output/history-memory-real3.log`,
`output/history-memory-build3.log`, `output/history-memory-types3.log`.
Сборка прошла, Svelte/TypeScript — без ошибок и предупреждений;
ESLint изменённых файлов и проверка размеров модулей прошли.

В штатном Electron прошли пять затронутых browser-сценариев: длинная история
и её полное копирование (2 544 105 символов), большая история задачи
(777 записей, 24 смонтированные строки), восстановление большого чата,
локальное эхо и настоящий вопрос Codex с барьером и продолжением той же
native-сессии после перезапуска. Лог: `output/history-memory-browser.log`.
Локальное эхо — 14,1 мс в данном прогоне. Холодное восстановление:
первый контент — 1221 мс, история — 1288 мс от создания OS-процесса.
У большого чата зафиксированы renderer long tasks 61, 112 и 50 мс;
это не подтверждает отсутствие пауз отрисовки.
Окончательный Windows ASAR также прошёл те же пять browser-сценариев
(`output/history-memory-packaged.log`). Локальное эхо — 14,4 мс,
первый контент — 1046 мс, история — 1079 мс от создания OS-процесса.
В этом прогоне остались renderer long tasks 75 и 81 мс.
Хеши main, background worker, native worker и preload внутри пакета
совпали с окончательной сборкой (`output/history-memory-package-integrity3.log`).
Пакет собран локально; установка и публикация не выполнялись.

Docker Engine недоступен: при закрытии настоящего приложения зафиксирована
ошибка подключения к `dockerDesktopLinuxEngine`. Контейнерный цикл
в этом этапе не проверен и не подменялся.

## Оставшиеся ограничения

Полная каноническая модель активной беседы всё ещё находится в основном
процессе. Учёт памяти не превращает её в дисковую командную модель.
Механизм освобождения восстановимых копий main-процесса проверяет давление
при открытии беседы; активная работа и неотвеченные вопросы не вытесняются.

Структурные события в read-model worker по-прежнему могут восстанавливать
и перегруппировывать полную историю; быстрый дисковый путь относится к
пакетам только из `item.append`. Одно огромное сообщение, output или diff
тоже остаётся целой записью. Их обработка, санитизация и DOM требуют
отдельного ограничения объёма работы. Эти ограничения данным этапом
не объявляются решёнными. Последующее исправление списка бесед
описано в [отчёте о каталоге чатов](chat-list-performance.md).
