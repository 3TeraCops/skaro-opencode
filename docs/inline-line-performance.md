# Огромная строка встроенного diff

Продолжение [оптимизации больших записей](record-text-performance.md). Данные —
существующая история чата в изолированной копии реального профиля; приложение
запускается со штатным backend/Electron. API, строки и события не подменяются.

## Подтверждённая причина

Записанный HTML diff содержит 1 044 507 символов и 512 строк. Самая длинная
строка — 211 737 символов. Виртуализация строк оставляла её целиком в DOM,
когда пользователь прокручивал к ней: общий размер ленты уже не определял
число узлов, но размер одной записи всё ещё определял работу layout.

`output/line-baseline.log` и настоящий browser trace: в DOM 211 737 символов;
максимальная задача renderer 88,5 мс, Layout 51,8 мс. Сценарий прошёл
функционально; паузы при этом не объявляются устранёнными.

## Реализация

Короткие строки сохраняют прежний `span`. Для длинных используется тот же
readonly-движок с горизонтальными промежутками, что и у вывода команды.
Порог 4000 символов соответствует области, где движок начинает создавать
такие промежутки; исходный текст не обрезается. Полный текст остаётся в модели.
Внешний `fd-diff` по-прежнему владеет прокруткой и измеренной worker шириной;
знак строки, diff-цвет, отступы и высота сохраняются.

Модуль загружается при запросе страницы с длинной строкой. До его готовности
страница использует существующий placeholder `WindowedContent`; отдельное
состояние интерфейса не добавлено. `DiffText` владеет только монтажом и
освобождением текстового представления. Общий readonly-конструктор и общий
механизм копирования используются также выводом команды.

Ранний вариант пересоздавал внутренний editor при изменении выделения:
внешняя строка и её wrapper сохранялись, а прежний `.cm-content` отсоединялся.
Причина — прямое чтение props из реактивного объекта строки в эффекте,
который создаёт императивный renderer. Теперь текст и функция создания
проходят через отдельные `$derived`; конструктор выполняется в `untrack`.
Жизненный цикл зависит от фактических входов, а не от инвалидирования
объекта строки. Настоящее выделение мышью проверяет сохранение того же DOM.
Неудачные варианты не выдаются за пройденную проверку:
`output/line-packaged2.log`, `output/line-selection2.log` и диагностические
`line-pointer*` / `line-*diagnostic.log`.

## Проверки

Сборка `output/line-build4.log`, типы `output/line-types4.log` (0 ошибок и
предупреждений) прошли. `output/line-native4.log`: расширенный native-сценарий
прошёл с настоящими мышью и clipboard. В начале длинной строки в DOM 2077
символов, у горизонтального конца — 2082. Высота 19,5 px, прежние шрифт,
цвет и отступы. Скриншоты сверены с предыдущим пакетом.

Проверены конец/начало строки, фрагмент после горизонтальной прокрутки,
выделение через невидимый участок, вся строка целиком, полная история при
смонтированном readonly-view, вертикальная прокрутка и повторное открытие.

Trace того же расширенного сценария: максимальный Layout 3,6 мс. За всю
последовательность observer зафиксировал одну задачу 61 мс: trace показывает
её после выделения всей строки, в кадре с обработкой Ctrl+C и Paint, а не
прежнюю полную переразметку текста. Это ограничение замера не скрывается.
Итоговый Windows-пакет без тяжёлого tracing: весь расширенный сценарий
прошёл без задач renderer дольше 50 мс. `output/line-packaged4.log`:
первая реакция 23,2 мс, первый текст 167,8 мс, 2077/2082 символа в DOM.
Проверочный переход до полной ширины, включая Playwright, — 750 мс;
он не является временем блокировки или первого текста.

`output/line-package4.log`: пакет собран без установки и публикации.
Побайтовая проверка всех 379 файлов `out` с ASAR прошла. Сборка/типы и
`output/line-lint-final4.log`, `output/line-e2e-lint-final4.log` прошли.
Изменённые кодовые файлы проверены на ограничения размеров и отдельные
ответственности; нарушений NO GOD не обнаружено.

В первом финальном прогоне пять сценариев прошли, проверка второй большой
команды остановилась, пытаясь открыть ещё не смонтированную вложенную строку.
Проверка теперь сначала прокручивает её в виртуальное окно и подтверждает
раскрытие группы; native click не заменён force/retry. Повтор на том же
пакете (`output/line-command-confirmation4.log`) прошёл для обоих выводов.
Продуктовый код между этими прогонами не менялся.

Итого проверены шесть затронутых сценариев: встроенный diff, выводы команд,
модальный diff, полная история чата, настоящее сообщение Codex и восстановление
C4-чата. Copy покрывает видимые фрагменты, невидимый промежуток, строку с
заголовком и полную ленту. Echo сообщения — 16,3 мс. Восстановление первого
контента — 1285,37 мс от создания OS-процесса, истории — 1318,47 мс.
Это новый замер оставшейся задержки, а не заявление об исправлении запуска;
код его критического пути этой работой не изменён. Профилируемый переход
C4-истории всё ещё имел задачи 73/71/51 мс и разрыв таймера до 162 мс.

## Границы

Полные исходные payload пока остаются в активной модели renderer. Эта работа
ограничивает DOM и стабилизирует взаимодействие; она не завершает чтение
отдельных больших записей из хранилища порциями. Огромные Markdown-блоки и
критический путь запуска остаются отдельными незавершёнными участками общей
задачи. Полный suite и контейнерный цикл не запускались; Docker Engine
недоступен. Релиз, установка и публикация не выполнялись.
