# Первый кадр списка чатов

## Проблема

На настоящем снимке восстановления C4-чата история уже видна, но список
бесед содержит только pulse-заполнители. Метаданные бесед при этом уже
находятся в локальном индексе. `ChatList.read()` ожидал текущий backend
refresh даже для уже известных строк.

## Изменение

`startup-chat-catalog.ts` читает максимум две страницы по 16 записей через
существующий `ChatCatalogReader`. Выборка выполняется только для активного
проекта при восстановлении раздела чата. Истории, документы, tasks и полный
список бесед в первый кадр не загружаются. Read-only соединение закрывается
в `finally`; недоступность индекса оставляет прежний штатный асинхронный путь.

В `BootstrapState` передаётся ограниченный `chatCatalog`. `ChatList` принимает
его один раз при первом восстановлении; уже имеющиеся страницы возвращаются
без ожидания нового refresh. После ответа backend сохраняется обычное
обновление ревизии и загрузка других страниц. Повторное открытие контроллера
не переиспользует устаревший startup payload.

При перезагрузке renderer текущие признаки live накладываются через тот же
`ChatSessions.liveRows()`, который используется обычными query/page. На
холодном старте агентских процессов ещё нет. Для наложения не восстанавливаются
истории: выполняются только обращения по ID к уже существующей live map.

Новых UI-элементов, строк, иконок, цветов или состояний нет. Используются
те же `ChatSessionRow`, `WindowedContent`, существующий loader и архив.
Все беседы доступны через прежнюю пагинацию; 32 — размер стартового ответа,
а не ограничение каталога или функционала.

## Проверки до runtime

`output/startup-catalog-build1.log`: сборка прошла.
`output/startup-catalog-types1.log`: TypeScript/Svelte, 0 errors / 0 warnings.
`output/startup-catalog-lint1.log`: lint изменённых модулей прошёл.

На настоящей `output/r3/skaro.db` выполнен `EXPLAIN QUERY PLAN`:

- строки — `SEARCH c USING INDEX chats_catalog_order`;
- import-признак — поиск по `sqlite_autoindex_settings_1`;
- счётчики — поиск по ключу проекта в `chat_catalog_counts`.

Глубокого OFFSET в startup-пути нет: только 0 и 16. Полного сканирования
каталога, разбора native log и чтения project artifacts здесь нет.

## Границы

Изменение устраняет ожидание backend для первых строк. Оно не устраняет
постоянную стоимость старта Electron, все оставшиеся long tasks renderer
или стоимость глубокого OFFSET и поиска ранга выбранной беседы. Если
выбранный чат находится далеко за первой страницей, его позиция по-прежнему
уточняется обычным backend find; стартовый viewport истории сохраняется
отдельным существующим механизмом.

Первый пакетный прогон не прошёл: найдено смешивание страниц при обновлении
порядка списка. Исправление и дальнейшие проверки в отдельном тестовом
проекте описаны в [обновлении видимой области](windowed-refresh-performance.md).
Они выполняются на штатной сборке Electron. Окончательный пакет этого
исправления ещё не проверен; установка и публикация не выполнялись.
