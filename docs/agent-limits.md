# Оставшийся лимит подписки

По указанию владельца от 05.10.2026 в самом низу навигации проекта находится
«Оставшийся лимит» с иконкой `circle-gauge` и существующим горизонтальным разделителем
над пунктом. В свёрнутой панели остаётся иконка с подсказкой.

По дополнительному указанию владельца текст пункта уменьшен до существующего
токена 13 px. Справа появляется процент, когда у агента по умолчанию проекта
остаток пятичасового или недельного окна строго ниже 10%. Если оба окна ниже
порога, выводится меньший остаток; 0% также показывается. При остатке ровно 10%
или выше процент скрыт. Дробь отображается до одного знака с округлением вниз,
чтобы остаток ниже порога не выглядел как 10%.

Фоновая проверка выполняется при открытии проекта и каждые три минуты,
независимо от открытия модалки. Изменение агента по умолчанию немедленно
убирает прежний процент и запрашивает данные нового агента. Выбор другого
агента только в модалке не меняет индикатор сайдбара. Неизвестные значения
и ошибка запроса скрывают процент; они не принимаются за нулевой остаток.
При уходе с проекта таймер и подписка на его изменения освобождаются.
В свёрнутом сайдбаре процент доступен в существующей подсказке иконки.

Пункт открывает компактную модалку на существующем `Modal`. Переключатели
Claude Code/Codex совпадают с модалкой выбора агента (`AgentPicker`). При каждом
открытии выбран агент по умолчанию текущего проекта. Переключение в этой
модалке только меняет показываемый аккаунт; настройки проекта и задач сохраняются.

Под переключателями — остаток пятичасового и недельного лимитов в процентах,
полосы на существующем `Progress` и время сброса в локальном часовом поясе.
Подпись «Общий лимит аккаунта» поясняет область действия: расход в других
проектах, CLI и приложениях также учитывается провайдером.

Данные обновляются при открытии, выборе агента, вручную кнопкой «Обновить»
и раз в минуту, пока модалка открыта. Внизу указано время последнего успешного
запроса. Поздний ответ предыдущего агента не заменяет данные выбранного.
При ошибке показано стандартное уведомление с возможностью повторить запрос.
Отсутствующие значения обозначены «—»: они не считаются нулём или полным лимитом.
Наступление времени сброса само по себе не меняет проценты до ответа провайдера.

## Источники и границы

- Codex: штатный `codex app-server`, запрос `account/rateLimits/read`.
  Именованный бакет `rateLimitsByLimitId.codex` имеет приоритет над совместимым
  `rateLimits`. Окна определяются по длительности 300 и 10080 минут,
  а не по названию `primary`/`secondary`. Остаток — `100 − usedPercent`.
  [Официальный протокол](https://developers.openai.com/codex/app-server/).
- Claude Code: установленный CLI через Agent SDK, control-запрос `get_usage`
  (`usage_EXPERIMENTAL_MAY_CHANGE_DO_NOT_RELY_ON_THIS_API_YET`,
  `skipBehaviors: true`). Читаются `rate_limits.five_hour` и `seven_day`;
  `utilization` этого ответа выражен в процентах 0–100. Этот интерфейс SDK
  экспериментальный и изолирован в адаптере; после обновления версии требуется
  реальная проверка. Он не совпадает с долей 0–1 в `rate_limit_event`.
- Запросы не передают пользовательский prompt и не обращаются к модели.
  Используются авторизация и установленные бинарники обычного контура Skaro.
  Renderer получает только окна и время проверки через типизированный IPC
  `agents.limits`; токены авторизации в UI не передаются.
- API-ключ, неподдерживаемая подписка, отсутствующее окно или изменение
  экспериментального протокола могут сделать данные недоступными. Интерфейс
  сообщает об этом, не рассчитывает остаток по количеству токенов задач.
- Дополнительные кредиты и квоты отдельных моделей в эту модалку не входят.
  Просмотр остатка не переключает рабочие задачи автоматически.

## Проверка

Проверяется настоящий Electron с отдельным разрешённым профилем, штатным
backend и установленными агентами. Заглушки API и renderer preview не используются.
Unit-проверки охватывают нормализацию процентов, неизвестные значения,
время сброса и классификацию окон из существующей реальной записи Codex.

05.10.2026: production-сборка, TypeScript/Svelte-проверки и четыре целевых
unit-теста прошли. В настоящем Electron проверены данные обоих аккаунтов,
выбор агента по умолчанию, ручное и автоматическое обновление через минуту,
повторное открытие, быстрые переключения с запросами в полёте и свёрнутый
сайдбар. Настройки проекта и run
проверочной задачи сохранились; ошибок renderer не было. Скриншоты сверены
с текущими компонентами и токенами. Ошибка сервиса и неподдерживаемая подписка
не воспроизводились искусственно; отсутствие данных проверено на уровне
нормализации. Новые компоненты меньше 180 строк, изменённые кодовые файлы —
меньше 300 строк. Полный набор тестов не запускался.

Дополнительная проверка индикатора: production-сборка, Svelte-проверка без
ошибок/предупреждений и два целевых теста прошли. Порог ровно 10%, нулевой
остаток, минимум двух окон, неизвестные значения и формат процентов проверены
чистыми функциями. В настоящем Electron на реальных аккаунтах проверены
появление 0% для Claude, отсутствие процента для Codex с остатками выше порога,
смена агента по умолчанию, независимость от выбора в модалке, быстрые изменения,
размер 13 px и `circle-gauge`. При закрытой модалке через три минуты наблюдался
реальный процесс фонового запроса установленного CLI; часы и IPC не подменялись.
Исходные настройки проверочного проекта восстановлены. Визуальная проверка
скриншотов прошла.
