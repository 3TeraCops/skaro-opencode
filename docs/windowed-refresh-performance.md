# Обновление видимой области каталога

## Причина дефекта

Последняя проверка списка чатов обнаружила две строки с одним ID после
перемещения выбранной беседы из глубины каталога в начало. Контроллер
сохранял старые строки при обновлении, но заменял страницы по мере ответа.
До прихода соседней страницы в DOM одновременно попадали разные порядки
одного каталога. Это нарушало уникальность строки и восстановление фокуса.

## Изменение

`windowed-pages.ts` хранит запросы и готовые страницы одной ревизии.
`windowed-controller.svelte.ts` публикует согласованное представление:

- При первом открытии готовые страницы показываются сразу. Стартовые
  индексированные строки не ждут загрузки соседних страниц.
- При обновлении прежняя видимая область сохраняется, пока её страницы
  и строка с фокусом не готовы для совместной замены.
- Параллельный переход к строке не публикует неполный новый порядок поверх
  прежнего. Ответы сброшенной ревизии и вытесненного запроса не возвращаются
  в кеш после завершения.
- Сохраняются размер страницы 16, кеш 12 страниц, защита видимой области,
  фокуса и выделения от вытеснения. Лимит кеша не ограничивает доступный каталог.

Компоненты строк, стили, порядок, тексты, действия и клавиатурная навигация
не менялись. Новых UI-состояний и зависимостей нет.

## Изоляция проверок

По указанию владельца Chatballs используется только для чтения. Старый
профиль `output/r3` не запускается для этих проверок.

Отдельный проект создан через штатный `projects.create`:

- ID: `dc52bd5f-1cd6-4705-adbd-7ffebb8540b6`;
- каталог: `output/performance-write-isolated/project`;
- отдельный профиль: `output/performance-write-isolated/profile`.

Подготовительная проверка выполнила 66 настоящих операций создания и отмены
чата через backend. Все команды отменены; native-сессии для них не создались.
Проверки сообщения и вопроса работают с настоящим Codex в этом проекте.
API, ответы и backend не подменяются. Проверка документа использует
существующий `docs/agent-output.md`, сохранённый штатным действием в отдельном
тестовом проекте; исходный документ не изменяется.

`live-profile-boundary.ts` проверяет реальный путь каждого зарегистрированного
проекта до запуска Electron. Требуется явно заданный
`SKARO_E2E_WRITE_PROJECT_ROOT`. Профиль с Chatballs или проектом вне этой
папки отклоняется. Та же проверка стоит перед изменениями копии SQLite
в проверке каталога. Отказ старого профиля проверен без запуска приложения.

## Границы результата

Окончательная сборка прошла (`output/window-pages-final-build.log`). Проверка
TypeScript/Svelte завершилась с 0 errors / 0 warnings
(`output/window-pages-final-types.log`), lint затронутых файлов прошёл.
Все изменённые в этом продолжении модули меньше 300 строк, компонентные
layout-файлы не расширялись. Кеш страниц и публикация представления имеют
раздельные обязанности.

`output/window-pages-final-browser.log`: все 6 целевых сценариев прошли
на окончательной сборке за 1,6 минуты. Полный набор тестов не запускался.
В каталоге во время проверки 69 настоящих бесед; смонтировано 58 строк
при прокрутке и 53 при восстановлении глубокой позиции. Документ содержит
59 681 символ, после проверки смонтировано 14 блоков; полное копирование
и открытие редактора сохранили исходный текст. Скриншоты каталога и документа
просмотрены; визуальных изменений относительно существующих компонентов нет.

Настоящий Codex прошёл вопрос, барьер, перезапуск и продолжение той же
сессии. Обычное сообщение получило настоящий ответ, локальное эхо появилось
за 29,7 мс. При полном перезапуске первое содержимое — 1629,83 мс,
история — 1731,43 мс от создания OS-процесса. Это отдельные замеры, а не
обещание таких значений при любом объёме данных. Сравнение отдельных
прогонов не используется как доказательство ускорения холодного старта.

Контрольные суммы рабочей базы Skaro, Git HEAD, состояния и отслеживаемых/
неигнорируемых файлов боевого Chatballs совпали с состоянием после
разрешённой очистки проверочных чатов. Проверка этих данных выполнялась
только чтением; профиль Chatballs для runtime-проверок не запускался.

Проверка каталога наблюдает DOM при обновлениях и после перезагрузок:
дублирование ID считается ошибкой, даже если оно исчезло до конечного assert.
Проверяются все страницы, архив и возврат, Tab/Enter, перенос выбранной строки
в начало и восстановление глубокой позиции после полного перезапуска.

Эти проверки относятся к отдельному проекту с короткими настоящими чатами.
Они не заменяют измерения огромной истории, большого C4-пакета, массового
выбора задач и отдельных тяжёлых записей. Холодный запуск Electron остаётся
измеримой задержкой. Требование мгновенной работы при любых данных целиком
не закрыто; установка и публикация не выполнялись.
