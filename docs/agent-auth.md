# Восстановление авторизации Codex

Задачи, чаты и интеграции используют один механизм в Codex-адаптере.
Повторный вход не прерывает работающие ходы и не перезапускает Skaro.

После успешного `account/login/completed` адаптер увеличивает ревизию
авторизации. Каждый процесс запоминает ревизию, с которой он был запущен.
Завершение хода с категорией `auth` или ошибка авторизации JSON-RPC также
помечает только соответствующий процесс как требующий восстановления.
Это покрывает повторный вход вне Skaro, после которого старый процесс
получает `unauthorized`.

Перед следующим ходом сессия проверяет состояние процесса. Если требуется
восстановление, она дожидается его остановки, запускает новый `app-server`
и выполняет `thread/resume` с прежним thread ID и `excludeTurns: true`.
Сохраняются рабочая папка, окружение, инструкции, MCP, выбранные модель,
усилие и права, режим планирования, проектор ленты и отложенные вопросы.
Старый выход процесса при восстановлении не закрывает поток событий сессии.

Восстановление выполняется между ходами. Принятый `turn/start` считается
активным уже по JSON-RPC ответу, даже если уведомление `turn/started` ещё
не пришло. Одновременные сообщения сериализуются: создаётся один процесс,
следующее уточнение отправляется через `turn/steer`.

Ошибка восстановления возвращается вызывающему коду. Сессия не подменяется
новым разговором, прежнее сообщение автоматически не повторяется. При
неподтверждённой остановке старого процесса новый не запускается. Закрытие
во время инициализации дожидается остановки создаваемого процесса.

## Проверки

Чистые тесты состояния: `session-auth.test.ts`, `turn-acceptance.test.ts`.
Проверка штатного контура: `session-recovery.integration.test.ts`; включается
через `SKARO_CODEX_BINARY`, указывающий на установленный закреплённый бинарник.
Она использует настоящую авторизацию и API, проверяет сохранение разговора,
изоляцию процессов, активный ход, одновременные сообщения и закрытие при
инициализации. Заглушки не запускаются, токены не изменяются и не отзываются.
Смена ревизии проверяет реакцию адаптера на событие входа; браузерный OAuth
и реальный отзыв токенов эта проверка не выполняет.
