# План: чтение задач без полного графа в renderer

Продолжение исправлений отзывчивости 19.10.2026 по поручению владельца.
Дизайн и поведение определяются [текущим baseline](ui-baseline.md).
Общий ход работы и прочие ограничения — [отзывчивость](feed-performance.md).

## Изменение контракта

Открытие плана больше не вызывает `tasks.list` и `plan.milestones`.
Общий `ProjectTasks` не хранит полный массив задач и не имеет режима
`retainFull`. План получает компактные сводки этапов с полным прогрессом,
числом задач и доступностью удаления, включая факты архивных задач.
Тексты цели и критериев читаются отдельно только для раскрытого этапа.

Строки каждого этапа читаются через `tasks.query` с видом `plan` и `tasks.page`
страницами до 16 записей. Порядок соответствует `order`, затем каноническому
порядку задач. Виртуальные строки сохраняют глобальные позиции, высоту и
доступ ко всему архиву. Клавиатурный перенос раскрывает и показывает целевой
диапазон; после завершения восстанавливается фокус. Отмена возвращает фокус
к исходному этапу. Pointer-перенос переиспользует существующий обработчик
с отменой, порогом движения и очисткой слушателей.

Рёбра зависимостей сохраняются в отдельной индексированной таблице `tasks.db`.
Видимая строка получает названия и статусы своих зависимостей, включая задачи
из других страниц и архива. Наведение получает прямые и обратные связи только
выбранной задачи; полный граф в renderer для этого не восстанавливается.
Проверка ревизии отделена от сводок: чтение диапазона, выбранных задач и связей
не пересчитывает общие счётчики при каждом запросе.

Архивирование и восстановление этапа используют `plan.archiveGroup`:
идентификаторы всех задач группы выбираются в worker и передаются штатной
операции backend. Renderer не получает полный массив для массового действия.
Первичные задачи, журналы и остальные пользовательские данные сохраняют
прежние форматы. Индекс зависимостей — восстанавливаемая проекция.

## Проверки

Штатный Electron и изолированная копия настоящего профиля, без подмены API.
В профиле 118 задач: 11 текущих и 107 архивных. Проверены страницы всех групп,
полные счётчики, порядок, доступность удаления и архивирования, названия и
статусы зависимостей, подсветка связей, позиция и отмена клавиатурного переноса.
Все архивные задачи прочитаны прокруткой при ограниченном DOM строк.
Настоящий полностью архивный этап восстановлен и возвращён в архив;
признаки архивирования всех задач после проверки совпали с исходными.

Проверены штатный Electron и собранный Windows-пакет. Сборка прошла,
проверка Svelte/TypeScript завершилась без ошибок и предупреждений;
проверки изменённых файлов ESLint и размера модулей прошли.
В пакете прошли сценарии документов, плана, переноса между этапами,
каталога задач, реакции на запуск и выбора задач по колонкам.
Подтверждение постановки задачи в очередь видно в первом кадре:
3,8 мс в этом конкретном замере; это не время завершения запуска агента.

Первая пакетная проверка окон задач прервалась при проверке фокуса после
переноса: окно закрылось, а восстановление настроек в finally также
завершилось ошибкой. Причина закрытия не установлена. Этот же сценарий
без изменения исходников прошёл отдельно и затем три раза подряд.
Исходный неуспешный результат сохранён в
`output/plan-pages-packaged-initial`; повторные логи —
`output/plan-pages-window-rerun.log` и `output/plan-pages-window-race.log`.
Визуально проверены план и архив в настоящем Windows-пакете;
новые элементы, тексты и стили не добавлялись.

## Оставшиеся ограничения

Сводки всех этапов, состояние раскрытия и DOM заголовков пока не имеют
страничного ограничения. Для проекта с очень большим числом этапов нужен
отдельный контракт диапазонов этапов. Ограничение строк каждого этапа
не устраняет линейную стоимость обработки всех сводок и раскрытых групп.
Текст отдельно взятого этапа и список связей одной задачи также могут быть
большими; их собственная ограниченная выдача пока не реализована.

Индекс текущей ревизии строится в worker; сбор сводок и пересоздание индекса
зависимостей пока линейны по числу задач и связей. Измерения настоящего профиля
не доказывают мгновенную работу при произвольном объёме данных.
Полный цикл контейнерной интеграции в этот этап проверки не входит.
