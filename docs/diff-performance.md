# Просмотр больших diff

Продолжение [работы над отзывчивостью](feed-performance.md). Дизайн — текущий код;
геометрия, палитра, номера строк, разделители, переключение файлов, обновление и
полный экран сохранены. Во время подготовки используется существующий индикатор
`WindowedContent`, без новых продуктовых текстов или элементов.

## Изменение

- Открытый просмотрщик удерживает свою строку в виртуальной истории, как карточки
  предложений. Прокрутка внешней ленты не должна уничтожать открытый просмотрщик.
- Разбор diff, подсчёт строк, расчёт исходной ширины и Shiki выполняются в browser
  worker. При смене файла или закрытии worker завершается; запоздавшие результаты
  не применяются. Рабочие потоки собираются как ES-модули, чтобы сохранить загрузку
  языковых грамматик по требованию.
- `DiffCode` создаёт только строки вокруг видимой области. Чтение — по 16 строк,
  кеш — 12 страниц. Общая ширина вычисляется по всему файлу, как в baseline.
  Число/высота строк задают прокрутку; измеренные строки корректируют её индекс.
- Выделение остаётся нативным. Ctrl+A/Ctrl+C копирует весь разобранный файл,
  включая невидимые строки. Выделенные строки удерживаются при прокрутке.
- Удалён прежний отказ от подсветки после 4000 строк: расчёт больше не занимает
  поток ввода/разметки. Старый и новый тексты по-прежнему сохраняют независимое
  состояние грамматики между строками.

## Проверка на реальных данных

Источник — записанное изменение HTML из существующего чата в изолированной
копии настоящего профиля: 1 044 507 символов, 512 строк. API не подменялся;
история, backend и Git настоящие. Искусственные записи не добавлялись.

В предыдущем проверенном Windows-пакете все 512 строк находились в DOM.
Наблюдалась долгая задача интерфейса 807 мс за последовательность переключений
файлов. Это ориентир исходного сценария: его окно измерения шире финального
замера отдельного HTML-файла, поэтому эти числа не объявляются строгим сравнением.

Два финальных прогона Windows-пакета:

| Проверка                                  |     Первый | Повторный |
| ----------------------------------------- | ---------: | --------: |
| Строк в DOM при открытии                  |  79 из 512 | 79 из 512 |
| Переход к тексту HTML, включая Playwright |     215 мс |    207 мс |
| Реакция кнопки до следующего кадра        |     5,5 мс |    6,8 мс |
| Долгие задачи до завершения подсветки     | 81 и 54 мс |     80 мс |

Первое нажатие проверено с удержанием 80 мс, без `force` и повторных кликов.
Перед поиском старой записи используется настоящее колесо мыши, отключающее
слежение за концом ленты. Ранние диагностические падения происходили из-за
конкурирующей программной прокрутки проверки и штатного слежения; это не выдано
за подтверждённый дефект нажатия в продукте.

Полная подсветка, прокрутка до последней строки, точное копирование всего файла,
возврат к началу, удержание окна при перемещении внешней истории и освобождение
строки после закрытия прошли. Геометрия и цвета сверены с настоящим предыдущим
пакетом: высота строки 20 px, `white-space: pre`, отступ кода справа 20 px;
скриншоты проверены визуально.

Сборка `output/diff-build3.log` прошла; `output/diff-types2.log` — 0 ошибок и
предупреждений; lint изменённых исходников и итогового сценария прошёл.
`output/diff-packaged-scoped.log` — 6 затронутых сценариев; дополнительно
`output/diff-confirmation.log` — 2 повторные проверки из-за ранее обнаруженного
сбоя проверки и более медленного замера восстановления окна. Полный suite
не запускался. Все 374 файла сборки совпали с локальным ASAR побайтово
(`output/diff-package-integrity.log`). Изменённые кодовые файлы проверены на
NO GOD violations.

Регрессионные проверки покрыли ES-workers документов/Markdown, C4-просмотрщик,
копирование всей истории, историю задачи, отправку настоящего сообщения Codex
и восстановление окна. Echo сообщения — 16,7 мс. Восстановление первого контента
от создания OS-процесса — 1,69 с и 1,31 с; самой истории — 1,74 с и 1,35 с.
Это ещё не соответствует требованию мгновенного запуска.

## Остаток

Полный разобранный массив и массив цветов пока передаются в renderer. Размер
модели зависит от файла, хотя DOM ограничен окном. Это не завершает переход
к хранению/чтению отдельных больших записей порциями.

Продолжение работы над внутренним diff (`DiffLines`) и полным выводом команды
описано в [отдельном отчёте](record-text-performance.md): ограничены DOM и выдача
страниц, проверены горизонтальная прокрутка и полное копирование. Там же указаны
исходные 79 мс на огромной строке diff и оставшиеся полные payload/огромный
Markdown-блок. [Следующий этап](inline-line-performance.md) устранил полную
переразметку длинной строки и сброс выделения; завершение всей оптимизации
не объявляется.
Полная проверка контейнерного цикла остаётся недоступной без Docker Engine.
