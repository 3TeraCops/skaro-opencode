# Холодный старт и обработка Markdown

## Найденная последовательная работа

Backend ожидал `ready-to-show`, прежде чем начинать создание сервисов.
В результате уже загружаемый renderer не мог получить историю до первого
показа окна и следующего этапа инициализации backend. Это ожидание удалено:
создание сервисов идёт параллельно загрузке renderer. Обработчики сохраняют
существующий promise готовности, проверку отправителя и обработку ошибок.
Сами сервисы, recovery, обновления и агентские функции не отключаются.

Отдельно проверена предварительная загрузка модуля сохранённого экрана
параллельно оболочке. Три замера без фоновой сверки файлов дали первое
содержимое 1345–1392 мс и историю 1524–1605 мс
(`output/startup-route-isolated.log`). Устойчивого выигрыша относительно
предыдущей версии не установлено. Эксперимент удалён; `main.ts` и
`ProjectSection.svelte` возвращены к состоянию до этого эксперимента.
Предварительная загрузка экрана не входит в результат.

## Markdown

Worker по-прежнему разбирает полное исходное сообщение. Вместо одного HTML
он возвращает части по завершённым Markdown-токенам. Разбор использует
единый lexer и определения ссылок всего документа. HTML с необособленными
контейнерами сохраняет прежний единый контекст разбора.

`MarkdownDom` очищает части той же политикой DOMPurify и присоединяет
готовый `DocumentFragment`. Браузер больше не получает сериализованный
очищенный HTML для повторного разбора. Между порциями обработка уступает
управление очереди ввода; неизменившееся начало ответа сохраняет свой DOM.
Изменившийся хвост заменяется только после подготовки первой замены.
Запоздавшая отменённая версия не продолжает присоединение частей.

Существующие ссылки, изображения по нажатию, копирование кода, Mermaid и C4
сохранены. Декорирование и обработчики действий выделены в
`markdown-interactions.ts`; DOM и его освобождение — в `markdown-dom.ts`.
Стили, структура HTML и тексты интерфейса не менялись.

каталог, три холодных запуска, документ и native replay. Проверка полного

а не доказанное нарушение восстановления после действий пользователя.
Сценарий исправлен: обычный переход в «Чат», выбор глубокой строки и ожидание
сохранённого выбора через настоящий backend перед закрытием.

`output/startup-markdown-restart-check.log`: документ, полный перезапуск
и native replay прошли, 3 passed. Таким образом проверены все пять целевых

Холодный старт по-прежнему занимает примерно 1,3–1,6 секунды;
стабильное ускорение показа истории этими замерами не установлено.

Проверена собранная Windows-версия из `out`, а не новый установщик или ASAR.

## Ограничение проверки большого ответа

в тестовом проекте. За 240 с полный ответ не завершился; сохранено 1057
символов итогового ответа и большой настоящий вывод чтения документа.
Native rollout также не содержит завершённого большого ответа. Причина
остановки генерации не установлена. Проверка большого ответа не пройдена.

Повторная генерация не выполнялась. Из `heavy-markdown-live.spec.ts`
удалено создание сессии: дальнейший сценарий принимает только явно указанный
ID уже завершённого большого ответа для локального повторного открытия.

Один огромный неделимый Markdown-токен, raw HTML, полный DOM готового ответа,
полный payload записи и структурное перегруппирование канонической истории
остаются ограничениями. Части по 8192 исходных символа — целевой размер
порции, а не ограничение размера отдельного токена или содержания.
Функционал не урезался; работа над произвольными тяжёлыми данными не завершена.
Установка, публикация и полный прогон тестов не выполнялись.
