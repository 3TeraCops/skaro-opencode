# Граф проекта: воспроизведение сценариев

Дата: 21.10.2026. Статус: контракт реализуется по поручению владельца;
результаты целевых проверок и оставшаяся приёмка — в [плане](project-graph-plan.md).
Часть [спецификации](project-graph.md), требования G-13—G-16 и G-20—G-25.

## 1. Назначение

Пользователь выбирает сценарий и видит, какие части проекта взаимодействуют,
в каком порядке, через какие границы и с какой ответственностью.
Воспроизведение основано на dynamic-представлениях принятой C4-модели.
Оно не выполняет код проекта, HTTP-запросы, задания очереди или операции БД.
Наличие описанного шага не доказывает фактическое выполнение/успех в работающей системе.

Один каталог сценариев доступен из самостоятельного раздела C4, графа и связанных
документов. В C4 сохраняется существующее динамическое представление;
анимированная карта открывается в Sigma с теми же view/relationship/element IDs.
Два независимых редактора или две противоречащие последовательности не создаются.

## 2. Формат и проверка

Источник — C4Model version 1: C4View.kind=dynamic, view.state и steps[].
Шаг содержит relationship и description. Отношение определяет source/target,
технологию, состояние и evidence. Порядок задаётся массивом, не геометрией графа.
Для UI ordinal начинается с 1; внутренний индекс — с 0.
Идентичность шага: snapshotId + viewId + ordinal. Одно ребро может повторяться.

Производная модель воспроизведения содержит:

| Поле | Смысл |
|---|---|
| snapshotId, c4Revision, c4Hash | Точное основание сценария |
| viewId, title, architectureState | Исходное представление и его current/planned |
| steps | Упорядоченные relationshipId, sourceId, targetId, description, evidenceRefs |
| participants | Уникальные реальные участники; исходные C4 IDs |
| diagnostics | Проблемы ссылок, состояния, покрытия и актуальности |

Проверяются исходная C4-схема, существование relationship/endpoints, принадлежность
представлению и разрешённое состояние через действующий c4AtState.
Неизвестное ребро или отсутствующий участник блокирует воспроизведение этого
сценария с конкретной причиной. Валидные независимые сценарии остаются доступными.
Пустой сценарий не получает выдуманный шаг или автоматически найденный маршрут.

Шаги current не подменяются planned-редакциями. Сценарий planned показывается
явно как планируемый, с соответствующей проекцией элементов/отношений.
Для mixed-исследования пользователь может видеть оба состояния, но проигрыватель
всегда фиксирует одно состояние исходного view.

## 3. Что означает последовательность

Шаги описывают сообщения/взаимодействия, а не маршрут одного физического пакета.
Источник шага N+1 может не совпадать с получателем N. В этом случае выделение
переходит к следующему источнику без дорисовывания соединяющего ребра.
Анимация не превращает асинхронный outbox в синхронный стек вызовов.
Технология и описание остаются доступны на каждом шаге.

C4 v1 не содержит машиночитаемых fork/join, условий ветвления, длительностей
и результатов. Упоминания retry, ожидания, таймаута, отмены или альтернативы
в description отображаются как описание; из текста не генерируется логика.
Повтор одного relationship в steps воспроизводится как отдельный явный шаг.

Так поддерживаются все корректные существующие сценарии, включая описание
восстановления после сбоя. Это объяснение модели, а не симулятор состояний приложения.
Структурные ветвления/параллельные дорожки потребуют отдельно согласованного
расширения C4, миграции схемы и проверки; они не вводятся скрыто ради анимации.

## 4. Управления и состояние проигрывателя

Состояния: idle, playing, paused, completed, invalidated, error.
Loading относится к загрузке сценария/подграфа, а не к шагу бизнес-процесса.
Сценарий открывается остановленным на первом шаге; автозапуск при открытии запрещён.
Отображаются название, состояние модели, номер шага N из M и его полный текст.

| Действие | Результат |
|---|---|
| Воспроизвести | Запускает текущий шаг; после completed начинает с первого |
| Пауза | Сохраняет шаг и прогресс анимации; не помечает шаг завершённым |
| Продолжить | Продолжает тот же шаг с сохранённой позиции |
| Следующий / предыдущий | Ставит на паузу и выбирает соответствующий шаг |
| В начало | Ставит на паузу, выбирает первый шаг, сбрасывает прогресс |
| Выбрать шаг | Ставит на паузу и фокусирует участников выбранного ordinal |
| Изменить скорость | Меняет визуальную скорость без изменения порядка/содержания |
| Закрыть сценарий | Останавливает таймер/частицы и восстанавливает исследовательский вид |

На первом/последнем шаге соответствующее действие недоступно; переход за границы
не происходит. После последнего шага — completed без автоматического цикла.
Точные подписи RU/EN, иконки и сочетания клавиш входят в design gate.
Предложены скорости 0.5×/1×/2×; это визуальный темп, не скорость backend.
Базовая длительность шага настраивается централизованно после визуальной проверки.

Пользователь может изучать детали участника без смены текущего шага.
Смена сценария останавливает предыдущий, очищает его эффекты и загружает новый.
Уход из раздела, скрытие окна/вкладки и потеря доступного Canvas ставят на паузу.
Возврат не запускает воспроизведение сам. Удаление проекта уничтожает его сессию.

## 5. Компоновка и камера

При открытии показываются все участники сценария и ближайший архитектурный контекст.
Остальная карта приглушается; участники не вырываются из своих подсистем.
Общая карта сохраняет мягкое движение и параллельные частицы по ориентиру видео.
Выбор сценария выделяет его связи внутри общей карты, не заменяя её маленькой
отдельной схемой. При пошаговом воспроизведении движение можно остановить для чтения;
оно не должно мешать удерживать участников в поле зрения. Полный экран не сбрасывает паузу.

Текущий шаг выделяет источник, получателя и ровно исходное отношение.
Ранее просмотренные шаги имеют спокойное вторичное выделение без обещания «успеха».
Если исходные узлы скрыты в группе, проигрыватель временно раскрывает их;
выход восстанавливает прежний набор раскрытий.
Фильтры пользователя сохраняются; несовместимый фильтр временно расширяется
явно для сценария и восстанавливается при закрытии.

Камера по умолчанию удерживает обзор сценария. Предлагаемое следование за шагом
включается отдельно и отключается при ручном перемещении/масштабировании.
Камера не прыгает к каждому ребру автоматически при чтении длинного сценария.
Reduced motion использует мгновенный фокус без анимированного перелёта.

## 6. Огоньки и отрисовка

Направленные частицы движутся source → target вдоль геометрии выбранного ребра.
Стрелка и текст сохраняют направление при отключённой анимации.
Частица возвращается только новым проходом; обратный пакет без отдельного ребра
не рисуется. Self-loop, параллельные/встречные рёбра имеют различимую геометрию.

Частицы рисуются расширением Sigma/WebGL, отдельно от Graphology-данных.
Нельзя каждый кадр менять все атрибуты графа, повторять layout или передавать IPC.
Часы анимации используют monotonic time и elapsed delta, а не число кадров.
Pause/resume, смена скорости, resize и scale сохраняют корректную позицию.
Устанавливаются пределы одновременно анимируемых рёбер/частиц и нагрузки GPU.

Режим исследования может анимировать явно выделенный направленный путь.
Фоновая анимация поддерживает жизнь общей карты; исследовательское выделение
или текущий шаг сценария добавляет более яркий слой. Одно и то же ребро не получает
две конкурирующие анимации. Частицы идут по многим связям параллельно с ограниченной
плотностью; неподтверждённые runtime-цвета «успех/ошибка» запрещены.

При отсутствии WebGL или потере context показываются согласованное состояние
и доступный текстовый список шагов/детали. Тихой подмены Sigma другим движком нет.
После восстановления context пользователь продолжает вручную с сохранённого шага.
Dispose снимает animation frame, resize/listeners, WebGL buffers и layout worker.

## 7. Версии и восстановление

Проигрыватель привязан к одному snapshot/C4 revision до завершения сеанса.
Новая редакция C4, удаление view/relationship или изменение выбранного checkout
ставят invalidated и паузу. Дальнейшие шаги не берутся частично из новой модели.
Можно заново открыть актуальный сценарий; старые сведения помечаются прежней редакцией.
Изменение только кода даёт stale-покрытие и паузу до явного продолжения старой
модели либо открытия обновлённого снимка; это не доказательство изменения сценария.

Локально сохраняются project/checkout, viewId, revision/hash, выбранный ordinal,
скорость, камера и положение деталей. После перезапуска всегда paused.
Прежний шаг восстанавливается только при совпадении основания; иначе открывается
актуальный сценарий с начала с объяснением изменения. Активный таймер не сериализуется.

Проверяется весь актуальный каталог dynamic, а не только эта выборка.

без hardcode. Сценарии из одного шага также воспроизводятся корректно.
Источники и IDs читаются из настоящего checkout; модель Chatballs не изменяется
для показа результата. Подробные уровни проверок — в [плане](project-graph-plan.md).
