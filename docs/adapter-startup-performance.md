# Граница CLI-аккаунта и SDK сессий

## Изменение

`ClaudeAdapter` больше не совмещает CLI-проверку аккаунта, SDK metadata,
резолвинг окружения и исполнение сессии в одном файле. Обязанности разделены:

- `account.ts`: прежние вызовы pinned CLI для статуса и входа;
- `runtime.ts`: единое разрешение executable, config-dir и окружения;
- `metadata.ts`: прежние модели, команды, MCP/skills/hooks и sandbox self-check;
- `adapter.ts`: композиция, загрузка SDK-функций по их назначению;
- прежние `session.ts` и `limits.ts`: сессии и лимиты, без переписывания протокола.

У metadata сохранены `try/finally` закрытия query и все преобразования ответов.
Прежний public export `ClaudeAdapterConfig` сохранён. Точки входа `./adapter`
и `./projector` позволяют импортировать конкретную обязанность без root barrel
с SDK-сессиями. Replay-worker и `session-log.ts` используют точки проекторов.
Новые зависимости и функциональные ограничения не вводились. UI не менялся.

Это отличается от [отклонённого переноса ранних импортов](startup-import-audit.md):
проверка аккаунта больше вообще не нуждается в SDK. Здесь нет переноса всей
инициализации backend за показ окна. Metadata всё ещё выполняется в main при
обращении к ней; перенос всей этой работы в отдельный процесс не реализован.

## Внешние ограничения проверки

В настоящих журналах трёх неуспешных сценариев установлены внешние отказы:

- Codex: `usageLimitExceeded`, успешный ответ и создание нового async-вопроса
  недоступны с текущим лимитом аккаунта.
- Claude: HTTP 403, `oauth_not_allowed_for_organization`, подписочный доступ
  к Claude Code отключён организацией. Native worker и SDK дошли до настоящего
  ответа провайдера, но успешная генерация не подтверждена.

В этих сценариях нет признака замены окружения или выдуманного ответа.
Optimistic echo Codex появился за 15,8 мс, но ожидаемый ответ не пришёл;
этого недостаточно для зачёта сценария доставки. До восстановления доступа повторные модельные вызовы не выполнялись. Логин, аккаунты и платежи не менялись.
Первоначальная проверка нового вопроса была заблокирована этим доступом;
результат повторного прогона после восстановления Codex приведён ниже.

В T-166 открытая проекция не содержала текущего вопроса; условная ветка
проверки сохранения вопроса не выполнялась и не считается подтверждённой.

Восстановление C4: первый контент 1134,14 мс, история 1176,44 мс от OS-процесса.
Long tasks 112/70 мс и разрыв таймера до 157,7 мс сохраняются.
Это не подтверждение мгновенного запуска или отсутствия пауз.

Повтор полного копирования прошёл без продуктовых изменений, в том числе
после прокрутки между Ctrl+A/C (`output/copy-selection-before.log`). Ещё три

нестабильность не воспроизвелась; её причина не объявляется установленной.
Проверка теперь выводит метаданные события и boolean-результат вместо
огромного содержимого буфера при отказе.
