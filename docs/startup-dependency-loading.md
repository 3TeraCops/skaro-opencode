# Причина ранней задержки запуска и изменение сборки

Проверка 20.10.2026 продолжает расследование выброса 5423,67 мс из
[проверки кеша страниц](history-page-cache-performance.md). Старый маркер
`main loaded` стоял после всех статических импортов и не позволял отличить
запуск Electron от загрузки зависимостей приложения.

## Установленная причина

Добавлена отметка до первого сгенерированного `require` основного entry.
Диагностика `SKARO_LOAD_TRACE=1` измеряет реальные вызовы загрузчика Node,
поиска файлов и синхронного чтения; оригинальные реализации выполняются
без подмены результатов. После вычисления entry все перехватчики снимаются.
В обычном режиме они вообще не устанавливаются.

`output/startup-load-probe.log` и соответствующий `cold-start.json`:

- Вход в JS entry — 171,59 мс внутренней шкалы main-процесса.
- `main loaded` — 5084,89 мс: между отметками **4913,30 мс**.
- Прямой импорт `yaml` с транзитивными зависимостями — **2262,73 мс**.
- Прямой импорт `electron-updater` с транзитивными зависимостями — **2619,42 мс**.
- Эти два неперекрывающихся импорта занимают **4882,15 мс**, более 99% паузы.
- База открывается уже после этого; в данном медленном запуске — 45,41 мс.
  В следующих двух запусках — 4,58 / 4,54 мс.

Следовательно, воспроизведённая многосекундная ранняя пауза находится в
синхронной цепочке загрузки двух внешних зависимостей. Electron до входа
в entry её не объясняет. Файл конфигурации не задавал исключения для этих
пакетов: штатный `externalizeDeps` electron-vite оставлял их в `node_modules`.
При запуске главный поток искал и загружал сотни отдельных модулей до
выполнения кода создания окна. Объём истории к этой конкретной паузе ещё
не имеет отношения.

В повторном измерении с отдельным учётом файловых операций
(`output/startup-load-io.log`, три запуска) получено 758 вызовов загрузчика,
625 операций разрешения имён и 234 чтения исходных файлов на запуск.
В этой серии выброс не повторился: ранние импорты заняли 316–338 мс.
Чтение заняло 52–53 мс, разрешение имён — 143–156 мс. Эти времена относятся
к этой повторной серии, а не к предыдущей медленной. Конкретный фильтр ОС
или причина медленного файлового доступа не профилировались; утверждения
об антивирусе на этих данных не делаются.

## Исправление

В `electron.vite.config.ts` добавлено:
`externalizeDeps: { exclude: ['yaml', 'electron-updater'] }` для main build.
Зависимости и их транзитивный код обрабатываются при сборке; старт приложения
больше не обходит их отдельные исходные файлы. Версии пакетов, YAML-парсер,
инициализация updater и порядок готовности backend сохранены. Работа не
переносится за первый кадр и не откладывает готовность обработчиков.

Диагностическая browser-проверка дополнительно запрещает внешние ранние
импорты этих двух пакетов, чтобы возврат такого пути загрузки был заметен.

## Результат в штатном Electron/backend

Только отдельный настоящий тестовый проект
`dc52bd5f-1cd6-4705-adbd-7ffebb8540b6`, профиль
`output/performance-write-isolated/profile`. Ни новых вызовов моделей, ни
обращений к Chatballs. Существующая история читается из настоящей базы.

`output/startup-bundled-browser.log`: 3 passed, включая три полных запуска,
восстановление глубокого чата и воспроизведение сохранённого native-журнала.

Ранняя цепочка теперь читает только три локальных chunk-файла; встроенные
модули Node/Electron остаются внешними. Восстановлен каталог из 71 чата;
native-журнал: 1407 исходных событий, 8 канонических записей, полное
копирование — 121858 символов. Оформление и renderer-код не менялись.

Отдельный контроль **без** `SKARO_LOAD_TRACE`,
`output/startup-bundled-normal.log`: 1 passed, ещё три полных запуска.
Первое содержимое — 1545,23 / 1093,34 / 1272,91 мс, отметка истории —
1181,13 / 1321,24 / 1343,71 мс. `main loaded` — 187,00 / 208,09 / 257,76 мс.
Диагностических отметок entry и перехватчиков в этом режиме нет.

Сборка прошла: `output/startup-bundled-build.log`; типы без ошибок:
`output/startup-bundled-types.log`; ESLint затронутых файлов без ошибок:
`output/startup-bundled-lint-final.log`. Новые/изменённые файлы диагностики
и конфигурации меньше 120 строк, отдельных UI-компонентов не добавлено.

Это запуски Windows-сборки из `out`, а не измерение нового установщика или
переустановленной ОС с гарантированно пустым файловым кешем. Установка
обновления, другие ОС и полный набор тестов здесь не запускались.
Первый видимый кадр и отметка истории — разные измерения: отметка истории
после двух animation frame не заменяет FCP. Выбросы сохранены в результатах.
Найденная ранняя цепочка устранена в проверенной сборке; оставшиеся
1–2 секунды полного старта и произвольный масштаб данных этим не закрыты.
