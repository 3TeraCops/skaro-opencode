# Сохранение страниц при служебных обновлениях

Продолжение работы над производительностью 20.10.2026.

## Причина и изменение

После разделения обработки служебных событий backend перестал пересобирать
архив, однако общая ревизия всё ещё заставляла renderer запрашивать видимые
страницы заново. Отмена незавершённого чтения также зависела от нового
объекта заголовка, поэтому событие лимитов могло отменить полезный ответ.

У `HistorySource` теперь есть отдельная `contentRevision`. Общая `revision`
продолжает возрастать при каждом событии и защищает заголовок от запоздалого
ответа открытия. Ревизия содержимого меняется при текстовом дополнении,
изменении записи, вопроса, разрешения, хода или откате истории. Служебные
события сохраняют её прежнее значение.

Производный индекс `feed_page_revisions` находится в worker-owned
`workspace.db`. Он записывается атомарно с проекцией. Для ранее сохранённых
проекций исходным значением служит общая ревизия; первое служебное обновление
сохраняет её без полного восстановления истории. Снимки и указатели без
нового необязательного поля продолжают приниматься.

Из `HistoryPages` выделен независимый от Svelte `HistoryPageCache`.
Renderer сохраняет загруженные объекты блоков и незавершённое чтение при
неизменном содержимом. Одновременные запросы одной страницы ожидают общий
результат. Запоздалый ответ после изменения содержимого отбрасывается;
его завершение не удаляет новый запрос. Ответ из более свежей структурной
ревизии запрашивает свежий заголовок через существующий reload сессии,
прежде чем попасть в кеш. Несколько таких ответов объединяют запрос
обновления. Отказ чтения не блокирует повторную загрузку после обновления
представления; успешно загруженные страницы сохраняются.

Размер страниц, лимит кеша в 12 страниц, закрепление выбранных блоков,
копирование и доступ к полной истории сохраняются. Стили, разметка,
тексты и состояния интерфейса не изменялись. Вложенные диапазоны получают
общую версию содержимого при чтении без перезаписи старых блоков.

## Остаток

Индекс содержимого пока общий для беседы: изменение одной записи может
перечитать несколько видимых страниц. Крупные поля хвоста по-прежнему
передаются в заголовке, а страницы содержат полные записи. Смешанные и
структурные события могут пересобирать архив. Огромные неделимые
Markdown-токены и нестабильность холодного старта остаются открытыми.
Эти проверки используют максимум восемь канонических записей в точках
служебных обновлений; произвольный масштаб ими не доказан.
Полный suite, установка и публикация не выполнялись.
